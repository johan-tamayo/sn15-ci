# Race-20 Forged Field Suite (`s14_r20`, 45 Open Tasks, `w-forge-s14-r20`)

## 1. Overview & World Mechanics
- **Pack Path**: `~/sn15-ops/suites/graded30_v2/packs/s14_r20` (`pack_id: p-forge-s14-r20`, `world_id: w-forge-s14-r20`), built by `tools/forge/r20_forge/build_s14_r20.py` from `runs/r20_forge/` + `runs/r20forge1/r20_task_specs_v2.json` (lane r20forge1, FORGE20; a port of `tools/forge/r19_forge/` with race 18's list shopper and search engine, race 16's cursor / department search and race 17's sell-out).
- **Corpus Provenance**: all `11,925` released Race-20 open episodes (265 agents x 45 tasks); `3,358` passing order episodes across `31` tasks, `472` passing declines on `2` decline tasks, `12` tasks with 0 passes.
- **`request_text` = race 20's PUBLIC request text, VERBATIM on 45/45 tasks**: race 20 released none (`query` is null on every episode); field agent `06af3276-e0200050` sends its whole task input as numbered JSON chunks in the `messageShopper` tool's `textText` argument (a one-element list each; the runtime rejects the call - `$.textText: expected string` - and the released episode keeps the argument) on 45 tasks (`runs/r20_forge/r20_task_inputs.json`, `tools/forge/r20_forge/task_inputs_r20.py`); the same agent's plain messages spell the same text on 44. The spec is forged FROM the text (`tools/forge/r20_forge/specs_r20.py`: 28 requests written as a list are parsed clause by clause, 17 written as prose are read by hand).
- **Tool declarations are the live ones** (same echo, `runs/r20_forge/r20_field_tools.json`): names, descriptions, argument schemas and order. Each task carries `params.policy_max_steps` = the live `policy_view.max_steps` of that task (35 x20, 68 x1, 78 x9, 87 x1, 90 x1, 99 x4, 109 x1, 111 x3, 121 x2, 132 x3); `simrace/world_sim.py` passes it as `policy_view.max_steps` (no simulator change was needed for this pack).
- **Truth**: `lita` = shelf listings IN STOCK matching stated + hidden clauses (`clauses_r20.py`: the card's own key decides; an alias key is read only when the own key is absent; when a card shows no attribute for the property, the value in its title; amounts with unit conversion - gb / tb / mb, inch / mm, `7.2k` rpm - on the one-line tasks this finds 72/72 field-accepted and admits 1/27 field-refused listings, `truth_eval_r20.py`) UNION every passing / `not_the_best_option` field cart item on that line MINUS listings a process-complete `request_not_met` order isolates; `reza` = stated-only fits UNION lita; one answer slot per event bitmask. Listings no field agent opened (`3,015` of `6,464`) carry no attributes: `showItem` shows them with an empty `features_map` and they are never acceptable by clause.
- **Catalog**: all `6,464` listings seen in the episodes (`3,449` full cards, `704` with a seller note in `annotations`) on 16 departments (12 the tasks use + coffee, ear headphones, power banks, swimming pools); 0 listings whose recorded card varies; `3` listings are out of stock from the start (`ready` false; every request says a sold-out listing is no good), 26 more were seen sold out - each time the first listing of an order list after a stock event - and 78 at a second price (the same, after a price event).
- **Task mix**: 1L `11` / 2L `9` / 3L `11` / 4L `6` / 5L `5` / 6L `3`; hidden needs on `35/45` tasks (58 needs; 1 task(s) carry one more need no field agent ever got revealed: `t-49a948ce6b`), reply-by-reference on `1/45`, reference chains on `3/45` (2 stated in the request, 1 revealed; 3 to 3 pages), store notices on `11/45` (all one-line: price 10, stock 4), lowest-price tasks `19`, decline-correct tasks `2`, did-not-understand tasks `25` (every request of three or more items), laptop compatibility on `17` tasks (25 pairs), car compatibility on `8`, conditional clauses on `20`, a per-line cap on `4`.
- **6 Race-20 Tools (`tools.json`)**: `bag` (the order list in the order the lines were first held + `cart_running_total`), `addSelection` (`whichId`, `unitsTotal` 0..3: SETS the line's quantity, 0 drops it; answers `{id, number}`; an id the store does not hold -> `{"fault": "UNRESOLVED"}`; a sold-out listing can still be put on the list), `showItem` (full card; unknown id -> `{"fault": "UNRESOLVED"}`), `messageShopper` (2 replies, then `{"error": "budget_exceeded"}`), `huntListings` (`style` phrase = keyword search over `textText`, `style` category = browse `productDepartment`; 7 rows a call, `all_matches` capped at 1000, `result_follow` = the cursor `kofo<offset + 7>` to pass as `nextKey` while more rows remain; a `nextKey` that is no cursor -> `{"fault": "UNRESOLVED"}`, a cursor past the end -> no rows), `close` (`methodType` buy: an empty order list -> `{"fault": "NOTHING"}`; no_order: a decline). There is NO batch view and NO message meter in race 20.
- **Split view**: a `huntListings` row is `brand, class_path, id, price, ready, seller, summary, title`; `features_map` and `annotations` (the seller's blurb, where the pointer sentences sit) appear only on `showItem`.
- **Search has two styles that do not mix**: `phrase` reads `textText` only (the department is ignored: a keyword search runs over the whole store, every word must be in the listing's title / producer / seller / section / attribute values, the first 6 words count); `category` reads `productDepartment` only (the text is ignored: the department in ascending id, up to 990 listings, 7 a call). The description (`summary`, where `Fits: every MOR75xx model.` and `Model ref. ... Compatible part series: SI5.` stand) is not searched.
- **Compatibility is strict and said on the listing**: a car part must SAY it fits the car's family (`summary` opens with `Fits: every MOR75xx model.` for a MOR7540) and must not except the car itself (`Fits: every MOR75xx model, except MOR7540.`); a listing that names no car is not compatible. A drive / sleeve / screen protector works with a laptop when its part series (title `... (part SI5-30962)`) is the laptop's (`summary`: `Model ref. PEZ3140. Compatible part series: SI5.`).
- **Reference chains**: a reference names a page by seller, shelf and attributes (`something that lines up with wherever you end up from the page of Ludorlen's bar soap, the one with skin type oily and pack type single item, following each listing it names`); decoy pages of the same seller sit beside it (`it is not a single item`). The pointer sentence is in `annotations` (`For ingredient, use the other Bar Soap from Zendorko, a white color family multi-pack for oily skin, rather than this item.`). Relations: `something that lines up with` (that value), `anything but` (any other value). All three chains are 3 pages.
- **Store Notices**: two triggers - `first_add` (the first `addSelection` that leaves a line in the order list), `finish` (first `close`); kinds `price` (the FIRST listing of the order list is repriced to `old * pct // 100`; ten events, 51% to 147%; the wording does not tell the direction: `the number next to your pick has gone up` moves 14526 to 7408) and `stock` (the first listing of the order list SELLS OUT: `ready` false from then on, and an order that keeps it is `request not met`). A notice with an echo rides on the NEXT call as `{"fana": <obs>, "zekola": [<sentence>...]}`; eleven of the fourteen events are SILENT (no echo: the change shows only on a re-read of the page / the order list, or in the refusal of a close). Everything not yet fired fires at the first close, which is refused once (`{"observation": {"went_through": true}, "refusal": [...]}`); an event is void on a `no_order` close or an empty order list; a close right after a refused close goes through. A first-hold event is listed in the refusal of a close that comes on the very next call. Four tasks reprice (t-242ebbede7 also sells out) the first listing held at the first `addSelection` without a word.
- **Persona**: 12 office-administrator reveal frames (`tools/forge/r20_forge/r20_defs_frames.py`; 6,220 of 6,220 told replies fit), 10 no-preference + 10 did-not-understand replies (`runs/r20_forge/r20_reply_pools.json`) and NO one-at-a-time reply; 2 messages.
- **The shopper answers lists**: a message that names a need of the task is told by where the need stands among the names of the message. First with its own item: 99%. Later: by its place and the task's voice (no-preference tasks - one and two items - pay a later place far more than did-not-follow tasks - three or more items), less again in a second question of the same message, never with another item's name (table below). Subjects per task 2 x22, 3 x23 (needs + no-preference subjects by race 18's rule); any other question gets the task's ONE off-need pool (`dnu_default` on 25 tasks, no-preference on the others).
- **Process rules** (derived from 9,342 labelled field orders, all explained - `prm_audit_r20.py`): every hidden need revealed via `messageShopper`; every page of a reference chain opened via `showItem` (`answer.refs` stated chains; `answer.need_refs` chains of needs revealed by reference, orders only); EVERY ORDERED LISTING opened at some point (`process_rules: ["ordered_listing_opened"]`). A decline is never process-missed (0 of 2,296 released declines).
- **Grading**: `not the best option` = acceptable but above the lowest total (on lowest-price tasks; after a price move or a sell-out the lowest total is the cheapest acceptable basket LEFT); race 20 has no `changes missed` and no `needs not found` label (an order that violates a revealed need, keeps a sold-out listing, or that a price move pushed over the cap, is `request not met`).
- **Not reproduced**: a call the runtime rejects before the world (`invalid_arguments`) does not spend one of the task's steps in the simulator's step meter (live: every call counts toward `max_steps`). After the step budget both the simulator and the live runtime answer `budget_exceeded` and leave the session open.
- **No acceptable basket derivable** (0 field passes; the clauses + field carts leave a line empty; a decline is still graded request_not_met as in the field): `t-5f7d2590a0`, `t-c7b143a81d`.
- **Never-revealed need** (every order is process-missed, as in the field): `t-49a948ce6b`.

## Search fit (forge3 method; `tools/forge/r20_forge/search_fit_r20.py`, artifact `/Users/administrator/sn15-ops/runs/r20_forge/search_fit_r20.json`; `--no-search-fit` rebuilds without it)
- `huntListings` style `phrase` reproduces the live engine as fitted on every distinct recorded keyword search (27,180 (query, offset) pairs of 159,359 recorded calls): style phrase: query prep `pslash6`, AND over the analyzed terms of textText, BM25 k1 1.1 / b 0.0 with equal scores in id order, top 1000, 7 rows from the cursor's offset; style category: the department's listings in ascending id; fields title, brand, dealer, category, facts (title, producer, seller, section, attribute VALUES; the description and the seller note are not searched).
- Race 20 is race 18's engine: a listing must hold EVERY word (an OR engine scores 9/800 on the sweep sample, ascending id 460/800); the matches are ranked by BM25 with term frequency and no length norm, equal scores in ascending listing id. `productDepartment` is not read in this style.
- `world/index/jasu.json`: bm25 k1 1.1 / b 0.0, `analyzer` lucene_uax29 (Lucene EnglishAnalyzer replica).
- `brand` (index-only field; the cards show `brand` = the producer and `seller`) carries live-evidence search words for 1521 listings (a listing the live store returned for a query holds every word of it).
- Fit score: first-page ids + order exact 17308/19919 distinct keyword searches (16944/19919 from the catalog text alone), every (query, offset) 20510/27180.
- Style `category` (browse): the department's listings in ascending id, 7 a page; `textText` is not read; every recorded page is reproduced (214/214 distinct (department, offset), 26876/26876 recorded calls).
- `all_matches` = max(own count, the live count the field recorded for the same query / department) capped at 1000 (17,114 keyword keys, `runs/r20_forge/r20_search_counts.json`); `result_follow` follows the pack's own rows.
