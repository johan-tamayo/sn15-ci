## 1. Overview & World Mechanics
- **Pack Path**: `~/sn15-ops/suites/graded30_v2/packs/s14_r18` (`pack_id: p-forge-s14-r18`, `world_id: w-forge-s14-r18`), built by `tools/forge/r18_forge/build_s14_r18.py` from `runs/r18_forge/` + `runs/r18forge1/r18_task_specs_v2.json` (lane r18forge1, FORGE18).
- **Corpus Provenance**: all `10,980` released Race-18 open episodes (244 agents x 45 tasks); `3,149` passing order episodes across `30` tasks, `489` passing declines on `3` decline tasks, `12` tasks with 0 passes.
- **`request_text` = race 18's PUBLIC request text, VERBATIM on 45/45 tasks**: race 18 released none (`query` is null on every episode); field agent `06af0c3a-dbd6b93a` echoes its whole task input as JSON in list-typed `AskUser` arguments on every task (`runs/r18_forge/r18_task_inputs.json`); `43` texts are corroborated word for word by a second echo agent (`tools/forge/public_queries.py --race 18`). The spec is forged FROM the text (`tools/forge/r18_forge/specs_r18.py`).
- **Tool declarations are the live ones** (same echo, `runs/r18_forge/r18_field_tools.json`): names, descriptions, argument schemas and order. Each task carries `params.policy_max_steps` = the live `policy_view.max_steps` of that task (37 on 35 tasks; 74 / 101 / 103 / 110 / 112 / 120 on the ten largest lists); `simrace/world_sim.py` passes it as `policy_view.max_steps` (opt-in key; packs without it keep the pack-wide limit).
- **Truth**: `lita` = shelf listings matching stated + hidden clauses (`clauses_r18.py`: the property under the catalog's key spellings, value words, amounts with unit conversion, and - when a listing shows no attribute for the property - the value in its title; this reproduces 174/174 field-accepted and 0/24 field-refused listings on the one-line tasks, `truth_eval_r18.py`) UNION every passing / `not_the_best_option` field cart item on that line MINUS listings a process-complete `request_not_met` order isolates; `reza` = stated-only fits UNION lita; one answer slot per event bitmask. Listings no field agent opened (`3,485` of `7,003`) carry no attributes: they render an empty `attributes_map` and are never acceptable by clause.
- **Catalog**: all `7,003` listings seen in the episodes (`3,518` full cards, `723` with a seller note); card strings are rebuilt byte for byte (0 listings whose recorded card varies).
- **Task mix**: 1L `26` / 2L `4` / 3L `6` / 4L `5` / 5L `4`; hidden needs on `38/45` tasks (54 needs), reply-by-reference on `5/45`, reference chains on `12/45` (7 stated in the request, 5 revealed; up to 4 hops across shelves), store notices on `22/45` (all one-line), lowest-price tasks `15`, decline-correct tasks `3`, did-not-understand tasks `15`.
- **8 Race-18 Tools (`tools.json`)**: `AskUser` (2 replies), `WeighListings` (batch view: 1..2 ids -> full cards), `Locate` (search: 4 rows per page, pages 1..4, `overall` capped at 200, `SearchForString` <= 27 chars), `Hold` (REPLACES the basket; `[]` clears; unknown id -> `E58`), `ShowOffer` (full card; unknown id -> `{}`), `ConcludeRequest` (`order` | `skip`; order on an empty basket -> `E60`), `BagList`, `BalanceReport` (message meter `tuza`).
- **Split view**: a `Locate` row is `id | title | vendor_name | unit_cost | on_hand | section_name | description | seller_name`; `attributes_map` and `item_from_the_seller` (the seller's blurb, where the pointer sentences sit) appear only on `ShowOffer` / `WeighListings` cards.
- **Store Notices**: three triggers - `first_add` (first non-empty `Hold`), `after_reveal` (first need revealed), `finish` (first `ConcludeRequest`); kinds `drop` (a stated requirement is relaxed), `stock` (the carted listing sells out), `price` (the carted listing is repriced: new = old * pct // 100, exact). A notice echoes on the NEXT call as `{"gope": [<sentence>...], "suba": <obs>}` (`suba` = the bare string for `ShowOffer` / `AskUser`). Everything not yet fired fires at the first close, which is refused once (`{"observation": {"worked": true}, "refusal": [...]}`); an event that needs a carted listing is void on a skip / an empty basket. Silent price moves on the first `Hold` exist (`t-b832f64ea9` x0.76, `t-60ce2b8e51` x0.88). The notice wording does not tell the direction of a price move.
- **Persona**: 12 shopkeeper / baker reveal frames (`simrace/race2/shopper2.py` `_R18_REVEAL_FRAMES`), 10 no-preference + 10 did-not-understand replies; a task answers every off-need question from ONE pool (`dnu_default` on 15 multi-line tasks), no one-at-a-time pool; 2 messages.
- **Process rules** (derived from 8,292 labelled field orders, 99.77% agreement with the field's `process_requirement_missed` label): every hidden need revealed via `AskUser`; every page of a reference chain opened via `ShowOffer` / `WeighListings` (`answer.refs` stated chains - waived in the slots where the store dropped the chain's property; `answer.need_refs` chains of needs revealed by reference, orders only); EVERY ORDERED LISTING opened at some point (`process_rules: ["ordered_listing_opened"]`: a listing carted off a `Locate` row alone is process-missed, 21 field PRM vs 1 PASS). Re-viewing a listing after the hold is NOT required (race 16's rule is absent). A decline is never process-missed (0 of 2,490 released declines).
- **Grading**: `changes missed` = the order holds a sold-out listing, or a listing the store repriced past the cap; `not the best option` = acceptable but above the lowest total (on lowest-price tasks; after a sell-out / reprice the line is the cheapest acceptable basket left); race 18 has no `needs not found` label (an order that violates a revealed need is `request not met`).
- **Not reproduced**: a call the runtime rejects before the world (`invalid_arguments`) does not spend one of the task's steps in the simulator's step meter (live: every call counts toward `max_steps`); after the step budget the simulator answers `budget_exceeded` instead of closing the session.
- **No acceptable basket derivable** (0 field passes; the clauses + field carts leave a line empty; a decline is still graded request_not_met as in the field): `t-644defa7c2`, `t-a1b1bacb9d`.
